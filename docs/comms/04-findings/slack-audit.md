# Slack Communication Audit — May–Aug 2026

*Method: full read of #motion-by-design (May 1–Aug 4), #aurizn (May–Jun), #symons-clark-logistics (Jun), #resmed (early Jun), plus keyword sweeps ("urgent", "can anyone", "any update", "final") across #sa-power-networks, #fujifilm-aus, #maxm, #raising-children-respiratory and others. Times ACST.*

## How the workspace runs

- ~40+ channels, one per client, plus internal (#motion-by-design, #mbd-time-off, #sales-mbd). Clients are **not** in Slack — Dom, Yami and Andrea paste client emails verbatim into channels as the de facto brief/feedback mechanism.
- The backbone is **Yami's daily morning priorities post** (~08:15–09:00 every workday) with per-person bullets, hour budgets and deadlines.
- Tracking: pinned Slack "To-do list", ClickUp for timesheets, NAS (`smb://`) as file source of truth.

## 1. Briefing

Best briefs in the sample came from the Aurizn client via Andrea (slide-by-slide structures, attachments, explicit "first draft by COB Wednesday") and from Yami's Symons Clark video brief (audience, structure, key messages, *and* internal budget: "Total budget is 6 days… Copy/script 2–3 hrs max including revs").

- Work regularly starts before assets/info exist ("I did my best with what information I could find! haha" — press release drafted from a spec dump).

## 2. Feedback

Individual comments are usually **concrete** (exact copy changes, page-by-page lists — ADSTAR invite feedback even carried its own deadline). The systemic problem is **fragmentation**:
- One job's feedback splits across Slack drip-messages, Figma comments, Google Slides comments, annotated PDFs, email, and "feedback discussed in person" (no record).
- Serial one-liner QA: ten micro-messages where one list would do — Chi: "These are too minor Yami, I can make changes after client's revision."
- Principals lose track: "don't know what AOL feedback Yami is referring too" → "This was the feedback you left in the chat yesterday. I believe it is done."
- "Approved" gets re-opened: "Sorry to reopen this one – just noticed one of the disclaimers needs to be updated… (and every size variation)."
- Vague client feedback passes through untranslated: "is there anyway we can make it look more techi / innovation / forward thinking?"

## 3. Project management

- **Deadlines**: usually concrete at the day level; same-hour client demands accepted by default ("We need this in the next 45 min").
- **Status visibility is a genuine strength**: daily priorities, weekly retainer traffic-lights ("🔴 Over: 0 🎉 / 🟠 Close: Cole 3 hrs left…"), per-task hour caps, an emoji protocol (👀 📤 ✅ 🆗 🔴), a "Ready for Chi" QA status.
- **Cracks**: delivery/approval state is tribal — "not sure if this went off?" / "made changes. Not sure if it was approved." Yami's manual "Went off" messages are the only delivery log.
- **Version/folder chaos**: `…/SymonsClark_VehicleCheck_V03.pdf/SymonsClark_VehicleCheck_V04.pdf` (folder named after an old PDF containing the new one); duplicate project folders ("could you pls not create multiple folders of the same project"); "Can we name the file differently, as this is not V4 from the same file?" Kavindu proposed a folder standard on Aug 4 — the team already knows.
- **Chasing by punctuation**: "@design???", "@Sergio???", "can anyone ask Sergio if he has seen this message, please?"
- **Threads barely used**; client jobs interleave with lunch orders. Andrea experimented once: "I'm providing feedback under this thread so that it is easier to track" (Jun 16). No decision log — decisions live in pasted emails, findable only by scroll-back.

## 4. Responsiveness & clarity

- Turnaround is genuinely fast (ADSTAR invite: 4 versions in ~24h). Culture is warm and blame-free; people freely say "I'm stuck".
- "Can anyone help?" is the default routing (8 instances since April) — works at this scale, but everything bottlenecks on Yami; when she's sick the system degrades visibly.
- **NAS dependency is heavy and fragile**: most links are `smb://` (dead on mobile/off-network), the server went down May 26, and paths circulate in three notations (smb://, /Volumes/…, Z:\). Five storage surfaces run in parallel (NAS, Google Drive, Figma, Vimeo, Slack uploads).
- Recurrent client-facing file friction: PPT font-embedding failures ("this happened before, didn't it?"), outlined-font requests, files too big to email.

## Top 5 strengths

1. Daily per-person priorities post with hour budgets and deadlines (Yami).
2. Retainer/budget transparency — weekly traffic-lights, per-task caps.
3. Fast, reliable turnaround; "Updated, thanks [link]" completion norm.
4. Template-first efficiency mindset (Andrea) + internal QA gate before client (Yami/Chi).
5. Self-correcting process culture with high psychological safety — emoji protocol, Slack List, folder-standard proposal all invented bottom-up.

**Synthesis:** high-trust, high-tempo, unusually transparent about money and priorities — but it runs on one PM manually relaying email-based briefs and feedback across five disconnected surfaces. Biggest wins: consolidated feedback per version, a real sent/approved log, written briefs from principals, single-source clickable file links.
